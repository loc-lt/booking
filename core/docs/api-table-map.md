Generated by `docs/postman/flows_build.py` in the team's notes folder next to this repository;
do not edit by hand. Measured on 2026-11-04: the Postman scenario `booking-core-mvp`
(198 requests, 649 assertions,
0 failures) ran against an API with a SQL recorder, so every row
below is what the code did, not what a design document says.

- **Writes**: at least one successful call inserted (`I`), updated (`U`) or deleted (`D`) rows of
  that table. Calls answered 4xx are rolled back and not counted, except `/auth/login` and
  `/auth/refresh`, which commit on purpose (failed-login counter, revocation of a reused token).
- **Reads only**: tables read but never written by that API.
- Every signed-in request also reads `users`, `memberships`, `membership_roles` and `roles`
  (token -> user, `X-Tenant-Id` -> membership -> permissions). They are listed only for the
  `auth` and `people` groups.
- Step numbers refer to the scenario flows (`docs/postman/booking-core-mvp.postman_collection.json`).
