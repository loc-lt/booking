# Structure: every folder and file, and why

`core/api/` is one Django project that builds into one image, started two ways: Gunicorn
(the API) and `manage.py run_worker` (the worker). It has four Python packages and a test
folder. The rule that shapes everything: **a module may import another module only through
its `service.py`, and the kernel imports no module.** `import-linter` (`pyproject.toml`)
fails the pipeline otherwise.

```text
core/api/
├── manage.py                 Django entry point (DJANGO_SETTINGS_MODULE from .env, default app.settings.local)
├── .env.example              every variable, documented; copy to .env (git-ignored)
├── pyproject.toml            dependencies (runtime + dev group), ruff rules, pytest settings, the two import contracts
├── uv.lock                   exact versions of every package, generated by uv, committed
├── .python-version           3.12: the Python uv uses, same as the image
├── Dockerfile                python:3.12-slim + uv, packages in /opt/venv, non-root user, CMD gunicorn; the worker overrides CMD
├── .dockerignore             keeps .venv, tests and .env out of the image
├── README.md                 the short entry page
├── app/                      the Django project: settings, URL root, the docs pages
├── kernel/                   what every module shares; depends on no module
├── modules/                  one Django app per bounded context, ten of them
├── worker/                   a Django app holding only the run_worker command
└── tests/                    everything CI runs, cross-module, over HTTP, on real PostgreSQL
```

## Why these names

| Name | Why, and what it is not |
| --- | --- |
| `app` | The Django "project" package, the same role as `paihong_apis/app/`: settings, root `urls.py`, `wsgi.py`. Nothing business-related lives here. |
| `kernel` | Code every module stands on: tenancy, auth, errors, pagination, timers, idempotency, migration helpers. Not called `core` because the repository already has `core/` and the docs use "the core" for the whole product; not called `common` or `utils` because it is a layer with a rule (imports nothing above it), not a drawer. |
| `modules` | Matches the module list of `docs/architecture.md`. Each is a Django app with its own tables and migrations, so "a module owns its data" is literal: a model class lives in exactly one app. Nothing like `paihong_apis/core/models.py` with every model together. |
| `worker` | A Django app so it can hold a management command and be in `INSTALLED_APPS`; it owns no tables. One command, not two (`relay_outbox`, `run_jobs` were planned), because both loops share one poll cycle and one container. |
| `tests` at the top, not per module | Almost every test goes through HTTP and touches several modules (a booking test needs a tenant, a user, a site, a type, a resource). One `conftest.py` with the fixtures that build that world serves them all. |
| `service.py` | The one public door of a module. The name is deliberate: other modules call *services*, never models, selectors or views of another module. |
| `000N_db_rules.py` migrations | The hand-written SQL that Django cannot express: row-level security, composite same-tenant foreign keys, CHECK constraints, the exclusion constraint. Kept apart from the generated `0001_initial.py` so they are easy to find and review. |

## `app/`

| File | Does |
| --- | --- |
| `settings/__init__.py` | Loads `core/api/.env` into the environment (standard library, no interpolation) before any settings module runs. Shell variables win. |
| `settings/base.py` | Everything shared: `env()` helpers, `database_from_url()` with `ATOMIC_REQUESTS=True` (one request = one transaction, so `SET LOCAL app.tenant_id` lives exactly as long as the request), `INSTALLED_APPS`, the middleware list, `REST_FRAMEWORK` (our authentication class, our exception handler, ISO 8601 dates, throttle rate for `/auth/*`), the `JWT`, `WORKER`, `AUTH`, `EMAIL_*` groups, password validators, JSON logging. `USE_TZ = True`, `TIME_ZONE = "UTC"`. |
| `settings/local.py` | Defaults for a developer machine when a variable is missing: DEBUG on, database on `localhost:55433`, a local JWT secret, Vite origins for CORS, docs pages on, the team's notes folder for the docs hub. Then `from .base import *`. |
| `settings/test.py` | What pytest uses: test-only secrets, in-memory e-mail, no throttling, `CONN_MAX_AGE = 0`. |
| `settings/production.py` | `DEBUG = False`, `USE_X_FORWARDED_HOST` for Caddy. Everything else must come from the environment; a missing variable raises at start. |
| `urls.py` | `GET /api/healthz` (runs `SELECT 1`), `/api/v1/` including each module's `urls.py` in order, and the docs pages. |
| `docs.py` | The local docs hub at `/api/docs`: sign-in form, tenant picker, Swagger UI loading a copy of the contract with the tenant and idempotency headers made optional (the page fills them), ReDoc, the raw contract, and every markdown file of the repository and of the notes folder rendered in the browser. Only when `API_DOCS_ENABLED=true`; path checks keep it inside the allowed folders and never serve `.env` or Postman environments. |
| `wsgi.py` | Gunicorn entry. |

## `kernel/`

Shared by every module; imports Django, DRF and the standard library only.

| File | Does |
| --- | --- |
| `uuid7.py` | `uuid7()`: time-ordered ids for every table (`docs/backend.md`). |
| `models.py` | `BaseModel` (UUIDv7 id, created/updated), `TenantModel` (adds `tenant`), and the three infrastructure tables: `TransitionLog` (one row per status move of any object, insert-only), `ScheduledJob` (timers), `IdempotencyKey`. |
| `db.py` | Migration helpers that return `RunSQL` operations: `enable_rls(table)` (policy on `app.tenant_id`, `FORCE`), `same_tenant_fk()` (composite foreign key `(tenant_id, x_id)` so a row can never point into another tenant), `attributes_check()`; plus `violated_constraint()` and `sqlstate()` to read a database error. |
| `tenant_context.py` | The tenant of the current request or job in a `ContextVar`: `activate_tenant()` runs `SET LOCAL app.tenant_id`, `activate_user()` sets `app.user_id`, `tenant_scope()` is the context manager the worker uses per job, `fresh_tenant_context()` resets the variable per request (middleware). |
| `auth.py` | `AuthAdapter.verify()` checks signature, `exp`, `iss`, `aud` (JWKS or HS256). `JWTAuthentication` is DRF's authentication class: it maps `sub` to a core user through `modules.users.service.user_from_claims` (resolved by import path, so the kernel still imports no module) and returns a `Principal`. |
| `access.py` | `TenantAPIView`: the base class of every tenant endpoint. Reads `X-Tenant-Id`, activates the tenant, loads the caller's active membership and permission grants into `request.access` (an `Access` object), or raises 403. `require_perm()`, `require_somewhere()`, `require_any()` are what views call. |
| `permissions.py` | The 27 permission codes (`booking.create`, `payment.refund`, …) and their descriptions, served by `GET /permissions`. |
| `errors.py` | `ApplicationError` and its subclasses, one per contract error code: `ValidationFailed` (per-field errors), `BookingDenied` (reasons from the rule trace), `SlotTaken`, `InvalidTransition`, `StaleVersion`, `Unauthenticated`, `Forbidden`, `NotFound`. `problem_handler()` turns any exception, DRF's included, into RFC 9457 `application/problem+json` with a stable `code`. |
| `history.py` | `record_status()` and `history_of()`: `transition_log` rows for objects other than bookings (resources, payments, memberships), so every status change in the system is audited the same way. |
| `pagination.py` | Cursor pagination: `parse_limit()`, `paginate()` returning `{data, nextCursor}` with an opaque encoded cursor. |
| `idempotency.py` | `run_idempotent()`: stores the `Idempotency-Key` with a hash of endpoint and body; a replay with the same hash returns the first response, a different body is a 422. |
| `jobs.py` | Timers: `register_job(type, handler)`, `schedule_job()`, `cancel_jobs()`. Modules schedule inside their transaction; the worker runs due jobs through the registered handler. |
| `request_context.py` | `RequestIdMiddleware` (reuses `X-Request-ID` or makes one, echoes it, resets the tenant context), `current_request_id()`, and the JSON log formatter that puts request id and tenant id on every line. |
| `cors.py` | `LocalCorsMiddleware`: CORS for the Vite dev servers only; empty on servers because Caddy serves apps and API on one address. |
| `params.py` | `uuid_param()`, `datetime_param()`: query-parameter parsing that raises `ValidationFailed` with the field name. |
| `serializers.py` | `AwareDateTimeField`: rejects timestamps without an offset. |
| `devtokens.py` | `sign()` (used by identity to issue tokens) and `mint()` (development tokens, DEBUG only). |
| `management/commands/dev_token.py` | `python manage.py dev_token --sub x --email y`. |
| `migrations/0001_initial.py`, `0002_db_rules.py` | The three kernel tables and their RLS. |

## `modules/`

Ten Django apps. Every one has `apps.py`, `models.py`, `service.py`, `migrations/`; those with
endpoints add `views.py` and `urls.py`; those with request bodies that need more than a few
fields add `serializers.py`. Engine code gets its own file named after what it does.

| Module | Tables | Endpoints | Engine files |
| --- | --- | --- | --- |
| `tenancy` | `tenants` | none (platform commands) | `management/commands/create_tenant.py`, `add_member.py`, `seed_demo.py` |
| `users` | `users`, `memberships`, `roles`, `role_permissions`, `membership_roles` | `/me`, `/me/accept-invitation`, `/permissions`, `/roles`, `/members` | `constants.py` (system roles and their permissions) |
| `identity` | `user_credentials`, `refresh_tokens`, `auth_tokens` | `/auth/*`, `/me/tenants` | `consumers.py` (sends the invitation e-mail on `member.invited`), `management/commands/auth_link.py` |
| `resources` | `locations`, `resource_types`, `resources` | `/sites`, `/resource-types`, `/resources` and their actions | — (policy and field logic is delegated to `config`) |
| `config` | `policy_versions`, `field_definitions`, `object_schema_versions` | none (reached through `resources`) | `policy.py` (flowConfig ↔ body), `fields.py` (definitions → JSON Schema → value checks) |
| `availability` | `availability_rules`, `availability_exceptions` | `/availability`, `/sites/{id}/hours`, `/resources/{id}/hours`, `/availability-exceptions` | `search.py` (free-slot search; outside `service.py` to avoid an import cycle with booking) |
| `booking` | `bookings`, `booking_allocations` | `/bookings`, `/bookings/preview`, `/bookings/{id}/approve|reject|check-in|check-out|cancel` | `lifecycle.py` (`transition()`), `jobs.py` (the four timers) |
| `payments` | `payments`, `payment_events`, `refunds` | `/payments/{id}`, `/payments/{id}/mark-paid`, `/refunds/{id}/mark-succeeded`, `/payments/reconciliation`, `/webhooks/payments/{gateway}/tenants/{tenantId}` | the mock gateway signature in `service.py` |
| `rules` | `rule_set_versions` | `/rules`, `/rules/versions`, `/rules/versions/{v}` | `engine.py` (evaluation, pure), `jsonlogic.py` (the evaluator) |
| `events` | `outbox`, `processed_events` | `/events` | `consumers.py` (built-in subscribers), `relay_batch()` in `service.py` |

### What each file inside a module does

Using `booking` as the fullest example; the others follow the same shape.

| File | Does |
| --- | --- |
| `models.py` | `BookingStatus` (the nine contract statuses, stored as-is), `Booking`, `BookingAllocation` (the time range a booking holds on a resource; `effect` HOLD or LOCK; `closed_at` when released). The exclusion constraint that forbids two open allocations on one resource at once is in `migrations/0003_db_rules.py`. |
| `lifecycle.py` | `MOVES`: the allowed `(from, move) -> to` table copied from `docs/domain/booking.md`. `transition()` is the only code that changes `bookings.status`: look up the move, run its guards (check-in window, cancellation deadline), update, run the effects of the new status (allocation HOLD/LOCK/close, timers), write one `transition_log` row, emit exactly one event. `Actor` says who moved (user, system, gateway). |
| `service.py` | The public interface. `evaluate()` runs pipeline steps 1–6 and only decides; `create_booking()` runs it then step 7 (writes); `preview_booking()` is steps 1–6 as a dry run. The actions `approve`, `reject`, `check_in`, `check_out`, `cancel` each check permissions and call `transition()`. `mark_paid`, `mark_refunded`, `apply_payment_webhook` are the payment side of the lifecycle. `run_timer()` is what the worker calls. `list_bookings`, `get_booking`, `describe()` read. |
| `jobs.py` | Registers `MARK_NO_SHOW`, `AUTO_COMPLETE`, `APPROVAL_TIMEOUT`, `EXPIRE_HOLD` with the kernel's job runner; each runs `transition()` as `SYSTEM`. |
| `serializers.py` | Request serializers (`CreateBookingRequest`, `PreviewBookingRequest`, `RejectBookingRequest`, `BookingListQuery`) with the contract's camelCase names, and `booking_json()` that shapes the response (`status`, `history`, `appliedConfig`, `payment`). |
| `views.py` | One class per path, each method: permission check → serializer → **one** service call → `Response`. `POST /bookings` wraps the service call in `run_idempotent()`. |
| `urls.py` | The paths, kebab-case, no trailing slash. |
| `apps.py` | `AppConfig`; `ready()` imports `jobs` so the handlers register. |

Module-specific files elsewhere: `config/policy.py` (the JSON Schema of a policy body, and the
two-way mapping with the contract's `flowConfig`, units in seconds), `config/fields.py`
(`check_definitions`, `compile_schema`, `check_values`), `rules/jsonlogic.py` (`evaluate`,
`check`: the JSONLogic subset, tested against the shared example file), `rules/engine.py`
(`evaluate_rules` returns a `Decision` with a trace), `events/service.py` (`emit_event`,
`subscribe`, `relay_batch`), `identity/service.py` (`register`, `login`, `refresh`, `logout`,
`change_password`, `forgot_password`, `reset_password`, `send_invitation`,
`accept_invitation`, `guest`, `tenants_of`; tokens and links stored only as SHA-256 hashes).

## `worker/`

| File | Does |
| --- | --- |
| `management/commands/run_worker.py` | The loop: `relay_batch()` (deliver outbox events to subscribers, once each, with retries) then `run_due_jobs()` (claim due `scheduled_jobs` with `FOR UPDATE SKIP LOCKED`, run each inside `tenant_scope(job.tenant_id)` through its handler, mark done or retry). `--once` runs one pass, for tests. `--reload` (local only) restarts it when a Python file changes, through Django's own reloader. Stops cleanly on SIGTERM. |

## `tests/`

| File | Covers |
| --- | --- |
| `conftest.py` | Fixtures that build a world: a tenant with roles, a site with hours, people with memberships, resource types and resources, tokens; an `APIClient` wrapper that sets both headers. Switches the database role to a non-superuser so RLS applies. |
| `test_auth_and_tenancy.py` | Token checks (expired, wrong signature, wrong audience), membership checks, tenant A cannot see tenant B, the tenant context does not leak between requests. |
| `test_identity.py` | Register, login, lockout, refresh rotation and reuse detection, logout, password change and reset, invitation links, guest tokens, `/me/tenants`. |
| `test_people.py` | Roles, permissions, invitations, disable and enable, member lists. |
| `test_sites_and_resources.py` | Sites, hours, exceptions, resources and their status moves. |
| `test_resource_types.py`, `test_config_flex.py` | Types, policies, versions, restore, custom fields, adding and archiving fields, buffers and limits. |
| `test_availability.py` | Free-slot search, local time vs UTC, DST, buffers. |
| `test_bookings.py` | The pipeline over HTTP and the lifecycle actions. |
| `test_lifecycle.py` | Every allowed move works, every other move is `INVALID_TRANSITION`, one history row and one event per move (90 cases). |
| `test_concurrency.py` | Two parallel requests for one slot: exactly one succeeds, including the deadlock case. |
| `test_rules_engine.py`, `test_rules_api.py` | The evaluator against the shared example, deny beats allow, scope precedence, quotas; publishing with `baseVersion`, preview. |
| `test_payments.py` | Upfront payment, mark-paid, signed webhooks, duplicates, forged signatures, expiry, refunds, reconciliation. |
| `test_worker.py`, `test_flow_end.py` | Outbox delivery once per subscriber, retries, the four timers. |
| `test_seed_demo.py` | The seed command produces a usable tenant. |
| `test_docs_pages.py` | The docs hub is local-only and never serves files outside the allowed folders. |
